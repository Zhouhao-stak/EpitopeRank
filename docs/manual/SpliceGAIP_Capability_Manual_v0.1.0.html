Splice Intelligence Workspace · Capability Manual

SpliceGAIP 能力手册

从剪接事件，到可复现的生物学证据。

SpliceGAIP 是一个面向「已完成可变剪接定量结果」的 AI 分析智能体平台。它不接受 FASTQ，也不做比对； 它接收 rMATS / SUPPA2 / MAJIQ / LeafCutter / 华大 RNAref 的已量化事件表，然后用一个 会自己决策、会自我质疑、会调用外部知识、会写报告的智能体内核，产出可解释、可复现、可发表的分析结果。

四条设计红线

贯穿全部功能，不是口号，而是写进代码与报告模板的硬约束。

不可逾越的四条线
  1. 没有模型 key 也必须能跑完——规则决策 + 离线 fallback，不是放录像。
  2. 不得从坐标猜序列，不得把单样本描述性 PSI 说成「肿瘤特异」。
  3. MHC 结合预测 ≠ 抗原呈递 ≠ 免疫原性。
  4. 每一次降级、放宽、跳过，都必须写进报告的方法与局限性。

M1

数据智能接入

异构表格 → 标准事件表
已上线

核心用途

不要求用户先把数据整理成某一种格式。系统扫描目录（含子目录），识别表头与分隔符，判断「这是剪接事件表 / 表达矩阵 / 转录本定量 / 元数据」，再决定怎么接。

使用方式

  1. Web 进入「AI 流水线」上传文件或目录 → 自动出预览（只读表头与最多三行样例，不遍历全表）。
  2. 对未见过列名的表格，已配置的模型会拿到列名 + 样例，提出映射建议；建议必须通过「列是否真实存在」的校验，并由用户确认后才写入。
  3. 华大 RNAref 单样本报告（OC_001/OC_001.SE.xls 等）会先被识别，再由用户手工指定每个样本的生物学分组，系统合并为 standardized/AS_event_master.tsv + sample_metadata.tsv。
  4. 也可直接调接口：POST /api/ingest/preview → POST /api/ingest/groups → POST /api/ingest/apply。

输入 / 输出

项内容
输入.csv/.tsv/.txt/.tab、制表符文本 .xls、真 Excel .xls/.xlsx/.xlsm、对应文本表的 .gz
输出standardized/AS_event_master.tsv、sample_metadata.tsv、识别报告（每个文件的角色与告警）
拒绝表达量矩阵（FPKM / TPM / read_count）→ 提示「请另选剪接事件结果」；转录本定量（Bambu 等）→ 识别但不进事件流程

适用场景

  • 手上是华大 / 诺禾等公司的单样本剪接报告，只有描述性 PSI，没有 p 值。
  • 手上是各工具混用的历史结果，需要先统一再分析。
  • 不确定某个文件到底是事件表还是表达矩阵。
边界（必须知道）
  • 单样本报告没有组间检验，输出的 p_value / FDR 保持空白，不能据此声称显著差异剪接。
  • 分组永远由人确认，模型不猜分组。
  • 只有 p 值没有 FDR 时，通用接入器只能对当前完整事件表做 BH；如果公开文件只是显著子集，必须补原始完整结果的 FDR。
主要入口 Web「数据接入」 · POST /api/ingest/preview|groups|apply
M2

剪接事件解析与标准化

四类工具输出 → 统一事件契约
已上线

核心用途

把不同工具的输出折叠成同一套事件契约（event_id / gene_id / event_type / PSI / ΔPSI / p / FDR + 质量列），后续所有统计、排序、报告都建立在这一层之上。

使用方式

自动识别，无需手动指定解析器（目录里放对文件名即可）：

输入说明
SE.MATS.JC.txt 等 rMATS 5 类 + sample_metadata.tsv含 0-based → 1-based 坐标转换、逐样本 PSI 展开
SUPPA2 *.psi.tsvΔPSI 来自均值差或外部文件
MAJIQ TSV（含 dPSI / P(dPSI)）自动映射
LeafCutter *_cluster_significance.txt自动映射
AS_event_master.tsv直接读取（已是标准表）

输入 / 输出

  • 输入：上述任一事件表 + 可选 sample_metadata.tsv（sample_id, group, condition, tissue, batch）
  • 输出：内存中的 Dataset（events / samples / validation）+ 落盘的标准表 + 校验告警

适用场景

同一课题里 rMATS 和 SUPPA2 混用；换工具后想复用同一套下游；做跨项目比较前先对齐契约。

主要入口 splicegaip/splicing/parsers/

M6

自我质疑：预注册假设检验

下结论之前，先系统性地挑战自己的结果
已上线

核心用途

在下结论之前，先系统性地挑战自己的结果，被拒绝的检验直接变成报告里的局限性。

使用方式

hypothesis_testing: true 时自动在解读前执行，无需调用；CLI / 接口也可单独触发。

检验H0（原假设）方法
dpsi_shiftΔPSI 分布未偏离 0Wilcoxon 符号秩（小样本退化 t 检验）
direction_balance上调 / 下调均衡二项检验
event_type_bias显著事件类型构成 = 背景构成卡方拟合优度
coverage_confound效应量与测序深度无关Spearman 秩相关
gene_recurrence命中不集中于少数基因置换检验（1000 次）

输入 / 输出

输入为当前候选与事件集合；输出为逐项 p 值 + BH 校正 + 结论，写入报告 3.3 节与 Limitations。

实例

自动 ORF 重建

开发中新抗原阶段 3 的自动化
预期目标
输入事件表 + 参考基因组 FASTA + GTF/CDS 注释，自动按事件类型（SE / RI / A3SS / A5SS / MXE）拼接 novel transcript，判定 in-frame / frameshift，翻译至首个终止密码子，计算 junction_nt，并按 50 nt 距离规则给出 NMD 候选。
解决的问题
目前阶段 3 必须由用户提供「已重建的 ORF 表」，这是整条链路里人工成本最高、最容易出错的一步；没有它，新抗原分析对绝大多数用户直接断在第三步。
当前状态
docs/prompts/splice-neoantigen-pipeline.md 已把阶段 3 的方法学与字段契约写死（orf_source / frame_status / premature_stop / last_junction_nt），代码中明确声明「自动 ORF 重建尚未实现」。

依赖 / 风险
转录本注释版本必须与事件坐标一致；不同事件类型的拼接规则不同，误拼会静默产生假肽——因此必须有逐事件可追溯的拼接日志。

5.3　演进方向的三条原则

原则一

能力往下走，证据链不放松

从事件走到肽、走到 HLA，每多走一步就多一层强制声明与局限性，而不是多一层「看起来更厉害」的数字。

原则二

人工确认点前移而非取消

阶段 3 要自动化的是「重建 ORF」这个体力活，而不是「跳过确认」这个安全阀；P1 落地后仍要求人工抽查。

原则三

默认路径变强，回退路径保留

每个新机制（自适应、技能、假设检验、新抗原）都有开关或旧模式；scripted 模式被长期保留为行为等价基线。

5.4　读者最可能关心的三个判断

现在能用吗？

能。给一份 rMATS 结果，一条命令出报告，无需任何 API key。

新抗原能信吗？

能信「它做到了哪一步」，不能信「它证明了免疫原性」。阶段化设计就是为了让这句话可核查。

什么时候能上传 FASTQ？

路线图 Phase 2，属规划中；当前请在上游跑完比对与定量。

06

能力边界（明确不做什么）

这一节比功能清单更重要。以下八条不是「暂未实现」，而是刻意不做——做了就会产出不可辩护的结论。

不做原因替代路径
FASTQ 质控 / 比对 / 转录本组装Phase 1 定位为「下游分析」上游 STAR / HISAT2 + rMATS / SUPPA2，结果表喂给平台（P2 规划中）
从坐标猜 CDS / ORF 序列会静默产生假肽提供 frame-correct CDS，或等 P1 自动重建
对显著子集重算 BH统计上不成立提供完整事件表
把单样本描述性 PSI 说成肿瘤特异无组间检验提供配对 normal 与生物学重复
从事件 ID 反推蛋白序列同上阶段 3 显式输入
声称抗原呈递 / 免疫原性 / 临床有效需要质谱与功能实验实验验证（四聚体 / ELISpot / 杀伤）
把 GTEx 未检出等同于「正常组织不存在」可能只是不表达或深度不足序列层过滤 + 表达证据
无限自我重试预算三重上限停止并写入局限性
一句话总结

MHC 结合预测 ≠ 抗原呈递 ≠ 免疫原性。平台能给出「值得做实验验证的候选清单」，不能给出「这个肽有效」。
